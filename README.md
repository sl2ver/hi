# Codex 작업 규칙 (개인 템플릿)

시험 전에 직접 만든, 어떤 과제에나 쓰는 범용 작업 규칙입니다. 과제 내용이나 답안 코드는 들어 있지 않습니다.
플랫폼의 안전 지침·관리 설정·승인 방식은 바꾸지 않습니다.

## 쓰는 법
```
git clone --depth 1 https://github.com/sl2ver/hi ~/h
cp -n ~/h/AGENTS.md .
codex
```
- 작업 폴더에 AGENTS.md가 이미 있으면 덮어쓰지 않습니다. 그때는 `cp ~/h/AGENTS.md ./작업규칙.md`로 복사하고 Codex에게 "작업규칙.md를 읽고 따라"라고 말합니다.
- 이 안내는 터미널에서 `cat ~/h/README.md`로 다시 볼 수 있습니다.

## 진행 순서
단축어는 손을 대신하고, 판단은 내가 한다. 판단은 `판단: …`으로 내 말로 적어 보내야 기록에 남는다.

| 순서 | 내가 치는 것 | Codex가 하는 일 | 내가 할 일 |
|---|---|---|---|
| 1 | `codex` → `/status` → `/model` → `규칙` | 읽은 지시 파일과 단축어를 5줄로 요약 | 모델과 규칙이 제대로 잡혔는지 확인 |
| 2 | `정찰` | 정찰.md 작성 | 그동안 담당자에게: 결과물 형식 / 넣으면 안 되는 정보 / 기간·대상 기준 |
| 3 | — | — | 정찰.md 질문을 2개씩 보내기. 답이 안 온 번호는 바로 되묻기 |
| 4 | `설계` + 담당자 대화 붙여넣기 | 설계.md·지시문.md 작성(1번은 처음부터 끝까지 도는 최소 흐름, 2번은 검사.py) | 설계.md를 읽고 `판단: 목표 한 줄 / 확정 규칙마다 담당자 말과 대조한 결과 / 잠정으로 돌릴 것`을 내 말로 보내기 |
| 5 | `다음` (반복) | 한 항목 구현·확인 명령과 검사.py 실행·설명.md·커밋 | 바뀐 내용과 결과 파일을 직접 보고 `판단: 본 것 / 숫자 / 이상한 점`을 보내기 |
| 6 | `복습` (두 번째 터미널, `다음`을 기다리는 동안) | 방금 끝난 항목으로 질문 3개(하나는 틀린 전제), 내 답 채점 | 핵심 항목만. 답은 내 말로 직접 쓰기 |
| 7 | `검토` (두 번째 터미널) | 설계 대비 점검 보고 | 고칠 것 골라 다시 `다음` |
| 8 | `변경: 요청 내용. 내 판단: 규칙과 충돌 여부 / 되물을 것 / 영향 항목` | 설계 변경 이력(내 판단 인용) → 지시문 수정 | 범위를 담당자와 확인 |
| 9 | `동결` | 재실행·문서 정리 | 설명.md를 읽기 전에 핵심 함수 3개를 내 말로 3줄씩 `복습 설명: …`으로 보내 채점받기 → 설명.md 읽기 → 제출 |
